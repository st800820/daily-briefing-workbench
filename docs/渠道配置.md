# 各推送渠道配置指南

本文档详述每个推送通道的**申请、配置、验证命令与已知限制**。所有密钥最终都填写在 `config.json`（或通过网页后台），对应字段见 `config.example.json`。

> 通用前提：先 `cp config.example.json config.json`，再填下面的字段；或在网页后台「📡 推送渠道」逐项填写后点「保存配置」。

---

## 1. WxPusher（推荐 · 直达个人微信）

**落点**：个人微信「微信ClawBot」会话（或 WxPusher App）。
**优点**：无需企业微信、微信扫码即用、格式稳定、支持文本/HTML/Markdown。
**限制**：ClawBot 通道每 24h 窗口限 10 条，需在微信给「微信ClawBot」回消息续期（灰度中）。

### 两种模式
- **极简推送 SPT（免注册推荐）**：微信扫码打开 WxPusher → 我的 → 极简推送 → 复制 `SPT_` 开头 token。
  - 填：`channels.wxpusher.token = "SPT_xxx"`，`uids` 留空（自动发给自己）。
- **标准推送 AT_**：注册 wxpusher 账号 → 创建应用拿 `AT_` appToken → 接收者关注应用后拿到 `UID_`。
  - 填：`channels.wxpusher.token = "AT_xxx"`，`uids = ["UID_xxx"]`。

### 验证
网页后台点「WxPusher · 测试推送」，或命令行：
```bash
# 标准模式示例
curl -X POST https://wxpusher.zjiecode.com/api/send/message \
  -H "Content-Type: application/json" \
  -d '{"appToken":"AT_你的token","content":"测试","uids":["UID_你的uid"]}'
```

## 2. 企业微信机器人

**落点**：企业微信群。
**优点**：官方、免费、格式稳定（支持 text / markdown / image）。
**限制**：需有企业微信（企业/组织），机器人绑定在某个群里。

### 配置
1. 企业微信 PC 端 → 目标群 → 右上角「···」→ 添加群机器人 → 获取 Webhook URL（含 `key=...`）。
2. 填：`channels.wework.webhook = "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=你的key"`。
3. `msg_type`：`text`（推荐，原样多行）/ `markdown` / `image`。

### 验证
```bash
curl -X POST "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=你的key" \
  -H "Content-Type: application/json" \
  -d '{"msgtype":"text","text":{"content":"测试早报"}}'
# 返回 {"errcode":0,"errmsg":"ok"} 即成功
```

### 让成员在个人微信也收到（微信插件）
1. 管理员：企业微信后台 → 我的企业 → 微信插件 → 复制"邀请关注"二维码（7 天有效）→ 发给成员。
2. 成员：个人微信扫该码关注插件；并在企业微信 App `我→设置→新消息通知` 关闭"仅在企业微信中接收消息"。
3. 之后该企业微信群（含机器人早报）会在成员个人微信同步呈现。
- 限制：仅覆盖**企业微信成员**；全员群 >2000 人不同步；纯外部个人微信覆盖不到（用 WxPusher 解决）。

## 3. 钉钉自定义机器人

**落点**：钉钉群。
**优点**：企业协同场景常用，支持加签保障安全。
**限制**：需有钉钉组织与群。

### 配置
1. 钉钉 PC 端 → 目标群 → 智能群助手 → 添加机器人 → 自定义机器人 → 获取 Webhook（含 `access_token=...`）。
2. 若开启"加签"安全设置，复制 Secret（`SEC` 开头）。
3. 填：`channels.dingtalk.webhook`、`channels.dingtalk.secret`（未开加签则 secret 留空）。

### 验证（程序自动加签，此处演示原始调用）
```bash
# 未加签
curl -X POST "https://oapi.dingtalk.com/robot/send?access_token=你的token" \
  -H "Content-Type: application/json" \
  -d '{"msgtype":"text","text":{"content":"测试早报"}}'
```
加签逻辑（本项目已内置）：`timestamp` = 毫秒级时间戳，`string_to_sign = f"{timestamp}\n{secret}"`，HMAC-SHA256 后经 Base64 + URL encode，作为 `&timestamp=...&sign=...` 追加到 Webhook。

## 4. Server酱（兜底）

**落点**：微信「服务通知」。
**优点**：微信扫码即用。
**缺点**：排版串行、emoji 表现差。**默认不启用**，仅在 `DELIVERY_CHANNELS` 显式包含 `serverchan` 时才会用。

### 配置
1. 打开 sct.ftqq.com → 获取 SendKey（`SCT...`）。
2. 填：`channels.serverchan.keys = ["SCT你的key"]`。

---

## 5. 微信 Ferry（不推荐 · 需降级）

**落点**：文件传输助手 / 指定微信群。
**前提**：必须**降级微信到 3.9.12.51** 并安装 `wcferry==39.5.2`。作者出于"不降级"原则默认关闭。
**配置**：`WECHAT_ENABLED=True`、`WECHATFERRY_SDK_DLL` 指向 sdk.dll、`WECHAT_TARGET` 填 `filehelper` 或群 wxid。
> 风险自担，本文档不作推荐。

## 6. 多通道组合建议

| 场景 | 推荐通道 |
|---|---|
| 个人微信稳定接收 | WxPusher（ClawBot） |
| 公司内部群 + 成员个人微信 | 企业微信机器人（微信插件） |
| 钉钉协同群 | 钉钉机器人 |
| 三者兼顾 | 同时启用 WxPusher + 企业微信 + 钉钉（`DELIVERY_CHANNELS` 顺序即尝试顺序） |

> 注意：`config.json` 中每个通道有独立 `enabled` 开关；网页后台可单独"测试推送"验证，避免"配了却收不到"。
